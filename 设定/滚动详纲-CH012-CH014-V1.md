# 滚动详纲｜CH012—CH014 V1

## 使用说明
承接CH011正式LOCK后的第二阶段主线。核心主题仍为`被删掉的街区`。所有写作必须服从CH001—CH011有效LOCK，尤其保护：周砚稳定度12%、最高P1、无P2；榆安街异常为多职责系统不整齐退出；`现行地址服务映射缺失`只是接口层观察，不等于道路被正式撤销或已知删除者。

---

## CH012｜有人住着，系统却不认
### 核心目标
1. 从CH011章末`核榆安街现行地址服务映射责任链`直接推进，不重新解释整个案件。
2. 扩大样本，但只选少量真正承担功能的人物/商户，不做人口普查。
3. 重点表现现实损失：能缴费但不能建维修单；能配送却必须电话/人工指路；服务已经完成但材料/费用挂账失败；地址校验导致预约/开户/维修承接受阻。
4. 继续区分不同职责来源，不把物业、供水、燃气、环卫、地图、档案目录写成一个万能数据库。
5. 可以追到`使用方 → 上游映射维护责任`的一层更深断点，但不要在CH012完成CH013才负责的完整门牌/道路编码/物业/公共服务职责拆分。
6. 39号燃气五天前按原地址履约的反例继续有效，只证明燃气职责链当时仍认该地址。
7. P1继续只在局部、合法可查看对象上使用，禁止逐门牌扫描、全街地图、自动异常边界、自动找修改者、自动给修法。
8. 顾显/白箱处可以继续缺席；只有出现会伤人的现实风险时才允许有限风险建议，不能变成城市地址客服。

### 节奏要求
减少连续口头解释“只能证明什么／不能证明什么”。优先让业务后果自己表达证据边界。人物在做事、碰壁、转交、签字、结算、找路中体现规则。

### 章末方向
找到一个真实的地址服务责任转交点或维护接口，却发现“谁使用”和“谁维护”并不在同一职责链。留下CH013正式拆职责的入口。责任单位、修改者、机制和修法仍未知。

## CH013｜街名还在谁的账上
### 核心目标
1. 正式拆分榆安街相关职责：门牌、道路编码、物业住户/设备、公共服务、配送/地图等各自能证明什么。
2. 引入至少一个“看起来最官方但也只能证明自身职责”的记录，继续防止权威单源变真理。
3. 找出不同系统更新时间、同步机制或责任转交差异，让`现行地址服务映射缺失`从模糊现象变成可追踪的责任链断口，但仍不等于找到幕后修改者。
4. 周砚开始理解街区级修复不能只补一个字段，需要让多个真实责任方重新接上。
5. P1仍只做局部差异提示；P2禁止。

### 禁止
- 不把某个上游部门直接写成“删除榆安街的人”。
- 不一章恢复整条街所有系统。
- 不强接周成、七号工位、7·17、城维、终端来源。

### 章末方向
形成第二阶段可复用的“职责拆分＋现实闭环”方法雏形，为CH014进一步命名/抽象方法准备条件，但不要提前把完整理论变成万能公式。

## CH014｜谁负责让一条街存在
### 核心目标
1. 在CH012—013已经积累的现实责任链上，让周砚和沈闻溪第一次较系统地总结街区级异常验证方法。
2. 可以出现对`证据／记忆／因果`三类现实支撑的更清晰认识，但如果仓库尚未正式授权“三锚”术语，正文不要提前硬命名。
3. 选择一个具体、会伤人的现实业务断点完成阶段性修复，例如关键公共服务重新可承接，但不等于整个榆安街全部恢复。
4. 继续保护“恢复事实不等于恢复旧权利/旧形态”的第一阶段底线。

## 长期保护
- 周砚稳定度除非终端明确变化，否则保持12%。
- 最高权限P1；P2不提前。
- 顾显/白箱处专业、有用、非全知，不抢主案。
- 周成/七号工位慢推，不与榆安街强绑。
- 安澜417长期根因、历史房号、第二把夜值钥匙、旧支路用途仍未解。
