# XIAOSHUO3｜项目要求 V1.0

## 1. 依据与权限
- 灵感来源：`灵感/IDEA-001-V1.md`，固定产物提交 `c8a88a7ed771e20472f08d1ada1dd711821f7def`。
- 用户明确要求：参考番茄小说近期热门作品的抽象结构规律，追求强钩子、强反差、快速入事件、明确爽点/情绪承诺和持续追读；可以学习模板机制，不得复制具体作品。
- 固定规模：100章；每章正文8000—10000字，默认约9000字；全书预计80万—100万字。
- 本文件中凡标记“总监设计”的内容，均为本项目新增Canon，不伪装成用户原话。

## 2. 主赛道与商业定位（总监设计）
- 主赛道：男频向现代都市异常悬疑。
- 辅助元素：职业流、规则解谜、非人格化系统、群像成长、单女主慢热。
- 工作书名：**《凌晨零点，城市向我报修》**。这是内部工作名，后续可在不改正文Canon的情况下另做书名包装测试。
- 核心读者承诺：每个大单元都有一个“一眼能懂的现实故障”，读者能快速知道危险是什么；主角靠观察、维修技能、证据和选择解决，不靠突然开挂秒杀。
- 一句话卖点：**夜间维修工周砚每晚00:07会收到一张“现实故障工单”；若倒计时结束前修不好，城市会把被判定为“错误”的人或地点从记录和记忆里删掉，而第一张工单要修的人就是他自己。**

## 3. 核心差异化
1. 系统不是会聊天、卖道具、发属性点的传统系统，而是一台老旧城市维修终端，只给冰冷工单、倒计时和有限诊断信息。
2. “升级”不是战力数字，而是维修权限、调查能力和对城市规则的理解。
3. 异常的解决核心是“证据、记忆、因果”三类锚点的闭合，职业技能与社会关系都能成为解法。
4. 每次修复都有代价：周砚累积“遗忘负荷”，他的社会记录、他人在短期内对他的记忆、乃至他自己的私人记忆会逐步受损。
5. 反方不是纯恶组织。封存派认为牺牲少数异常对象换取大多数人的现实稳定是必要代价，形成长期价值冲突。
6. 长线主题不是“打败终极怪物”，而是“一个人的存在是否必须被多数人记得才算存在，以及真相与稳定如何共存”。

## 4. 创作硬约束
- 不复制任何现实热门作品的书名、人物关系组合、专属系统规则、标志性桥段、台词、简介或独特表达。
- 不把本作写成无限副本刷怪；每个异常单元必须推进至少一项：主线谜团、人物关系、世界规则、长期代价。
- 主角不可无代价全知；工单不会直接公布完整答案。
- 不可复活已经被明确确认死亡的人。可以恢复“被抹去的存在记录”或纠正身份，但不能逆转死亡。
- 不用连续巧合代替人物行动；关键解决必须来自前文已建立的信息、技能、证据或人物选择。
- 不靠降智反派制造爽点。封存科/白箱处的行为必须有稳定逻辑和真实风险依据。
- 不写后宫；感情线为周砚×沈闻溪的慢热单线，服从悬疑与人物成长，不喧宾夺主。
- 中文表达自然、具体、克制；禁止翻译腔、模板化排比、反复微表情、段末机械总结和为了凑字数重复心理。

## 5. 全书节奏指标
- 第1章：第一页内进入异常；中段明确失败代价；章末必须完成一次局部兑现并抛出更大的父亲线索。
- 前3章：完成“第一工单＋第二工单开局”，建立周砚、沈闻溪、工单机制、修复三锚至少两个概念。
- 每3—5章至少一次明确阶段兑现。
- 每10章形成一个阶段闭环并把长期谜团推进一级。
- 第40章前把“遗忘负荷”从隐性风险升级成伤害亲密关系的显性代价。
- 第60章前揭开父亲并非普通失踪；第70章前揭开城维协议来源；第80章形成“真相恢复也会伤人”的价值反转；第90章进入全城级倒计时；第100章完成核心承诺闭环。

## 6. 成功标准
- 读者在前三章能复述：主角是谁、工单是什么、失败会怎样、为什么必须继续接单、父亲线索是什么。
- 每个异常至少有可追溯规则和因果，不靠作者临时宣布答案。
- 主角能力增长与代价同步增长。
- 主要人物在100章内都有独立目标与选择，不只围着主角服务。
- 结局解决“城市如何稳定、被抹去者如何被承认、周砚与父亲/母亲/沈闻溪的关系如何落地”三类问题。
